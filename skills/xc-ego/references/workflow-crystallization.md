# 本机流程固化与结构化回复模板

当需要将单次或单轮多表/多步跑通的操作沉淀为本机可直呼复用的流程，或需要在开局匹配、完工询问、固化回执时读取本文件。

---

## 一、核心原则：路径固化、参数当次给定、选择权归用户

1. **只固路径与步骤骨架，不写死业务参数**：
   - 固化内容：平台（`hibo` / `meituan` / 跨平台 `mixed`）、入口 URL / Hash 路由、导航菜单路径、页签与导出/操作按钮骨架、是否为写操作、以及 `requiredParams` 参数名清单。
   - 不写死内容：中台、门店名称、渠道、日期（尤其禁止绝对日期）、修改数值等每次调用按需说明的参数。
2. **个人存储与公共仓库隔离**：
   - 固化流程以独立 JSON 文件保存至用户本机 `~/.xc-ego/workflows/<id>.json`；如需配合自定义本机脚本，仅可放在 `~/.xc-ego/workflows/scripts/`。
   - 禁止写入公共 Skill 目录，确保后续更新或覆盖 Skill 目录时个人流程不被覆盖。
3. **禁止自动固化与叠加提问**：
   - 严禁未经用户同意自动沉淀流程，也禁止静默记录或主动推荐默认筛选参数。

---

## 二、触发门控（何时询问、何时不问）

| 场景 | 动作 |
|---|---|
| 本次为**单项未固化新操作**，且已成功完成（含读/写操作） | 调用 `scripts/workflows.mjs`（`format-offer`），在完工汇报末尾按**模板 A1** 询问是否固化 |
| 本次对话包含**多张表或多步操作**并全部成功完成，且未直接命中既有整体流程 | 调用 `scripts/workflows.mjs`（`format-offer` 传入 `items`），在末尾按**模板 A2** 询问：**固化整体 / 固化单项 / 都要**（若其中某单项已固化，在对应 `items` 项设 `alreadySaved: true`） |
| 本次已直接命中本机固定流程（单项或整体）并按原路径执行完毕 | **不再询问固化**，直接交付结果 |
| 任务失败、中断、仅完成环境/登录体检、或非海博/美团任务 | **不询问固化** |
| 用户回复「固化」/「固化整体」/「固化单项…」/「都要」 | 按选择调用 `save`（`kind: "single"` 或 `"composite"`）或 `save-batch` 落盘，并原样输出**模板 B** 结构化卡片 |
| 用户未回复、拒绝或开始新任务 | 保持单次执行记录，不追问 |

> **写操作边界**：改起送价、改配送费、改价、报名或取消活动等写操作**同样支持固化**（单项或整体流程中的一步均可）。调用时由 Agent 依据当次指令明确度自主判断并完成提交，不做冗余二次确认；仅在缺关键参数、存在多义目标、页面状态异常或遇登录验证时停下询问。

## 三、结构化 Markdown 回复模板

以下文案均由 `scripts/workflows.mjs` 确定性生成，输出时保持其清晰符号、加粗与分层结构，不自行改成零碎数字流水账。

### 模板 A1：单操作完成后的固化询问（`format-offer`）

```markdown
---
### 📌 是否固化为本机固定流程？

- **固定路径**：{平台} · `{入口或页面路径摘要}`
- **每次按需提供**：{每次须说明的参数清单}（不写死）

👉 回复 **「固化」** 即可保存；不回复则仅作本次执行。
```

### 模板 A2：多表/多操作完成后的固化询问（`format-offer` 传 `items`）

```markdown
---
### 📌 本次完成 {N} 项操作，是否固化为固定流程？

**包含项目**
1. **{项目1名称}**（{平台} · `{路径摘要}`）
2. **{项目2名称}**（{平台} · `{路径摘要}`）

- **每次按需提供**：{合并后的参数清单}（不写死）

**请选择固化方式**（不回复则仅作本次执行）：
- ▸ 回复 **「固化整体」** → 将上述 {N} 项合并保存为 1 条串联流程
- ▸ 回复 **「固化单项」** 并指明序号或名称（如「只固化 1」）→ 仅保存指定单项
- ▸ 回复 **「都要」** → 同时保存整体串联流程与各单项独立流程
```

### 模板 B1：单条固化完毕说明（`save` 返回 `confirmationReply`）

- **单项流程（`kind: "single"`）**：
  ```markdown
  ### ✅ 已固化本机固定流程：「{流程名称}」

  - **固定路径**：{平台} · `{入口或页面路径摘要}`
  - **每次按需提供**：{每次须说明的参数清单}（不写死，随当次任务给定）
  - **下次调用**：直接说 **「{自然语言调用示例}」**，将自动匹配并调用此流程
  - **执行边界**：意图与参数齐备即直接执行完成；仅在缺参、存在歧义或遇登录验证时停下询问。
  ```
- **整体串联流程（`kind: "composite"`）**：
  ```markdown
  ### ✅ 已固化本机整体固定流程：「{整体流程名称}」（共 {N} 项，串行执行）

  - **固定路径**：{组合路径摘要}
  - **每次按需提供**：{每次须说明的参数清单}（不写死，随当次任务给定）
  - **下次调用**：直接说 **「{自然语言调用示例}」**，将自动匹配并按序执行全部项目
  - **执行边界**：意图与参数齐备即直接执行完成；仅在缺参、存在歧义或遇登录验证时停下询问。
  ```

### 模板 B2：批量固化 / 回复「都要」完毕说明（`save-batch` 返回 `confirmationReply`）

```markdown
### ✅ 本次共固化 {M} 条本机固定流程

**已固化清单**
1. **【整体】「{整体流程名}」**（含 {N} 项：{项目名1}、{项目名2}）
2. **【单项】「{单项1名}」**（{平台} · `{路径摘要}`）
3. **【单项】「{单项2名}」**（{平台} · `{路径摘要}`）

- **每次按需提供**：{合并后的参数清单}（均不写死，随当次任务给定）
- **下次调用**：说整体流程名按序执行全套，说单项名单独执行该项（如 **「{整体示例}」** 或 **「{单项示例}」**）
- **执行边界**：意图与参数齐备即直接执行完成；仅在缺参、存在歧义或遇登录验证时停下询问。
```

## 四、`scripts/workflows.mjs` 调用契约

按 `SKILL.md`「跨平台脚本调用约定」通过 `ego-browser nodejs` 或 `node <skill_dir>/scripts/workflows.mjs --request <abs_request_json>` 调用：

1. **开局匹配（`match`）**：
   ```json
   {
     "action": "match",
     "query": "导出订单数据，小仓，章丘店，美团，昨天"
   }
   ```
   - 返回 `status: "exact"` 或 `"matched"` → 取出 `matched`（`kind: "single"` 用 `pathSpec`/`steps`，`kind: "composite"` 按 `subTasks` 顺序串行执行；部分匹配会自动按 `isWriteOperation` 区分纯读与改写指令）；
   - 返回 `status: "multi"` → 单句同时命中多个互不重叠的既有单项流程（`matchedList` 按出现顺序排列），依次串行执行每项，全部完成后按**模板 A2** 询问是否固化为整体串联流程（对应单项设 `alreadySaved: true`）；
   - 返回 `status: "ambiguous"` → 停下列出 `candidates` 请用户指定；
   - 返回 `status: "none"` → 按常规页面路径执行，并在完工后按模板 A1/A2 询问；
   - 若返回 `warnings`，说明 `~/.xc-ego/workflows/` 中存在损坏的单个流程 JSON 文件（已自动跳过），可在回复中附带提醒。

2. **生成询问文案（`format-offer`）**：传 `items`（多步）或 `platform`、`pathSummary`、`requiredParams`（单步）。

3. **固化保存（`save` / `save-batch`）**：脚本会自动校验并拦截写入 `pathSpec` / `subTasks` / `steps` 的绝对日期及写死业务参数（`brand`、`stores`、`channel`、`date`、`price` 等），确保固化文件只存纯净路径骨架。

4. **查看与清理（`list` / `delete`）**：
   - `{"action": "list"}`：列出本机全部已固化流程；
   - `{"action": "delete", "id": "每日两表导出"}`（或传 `name`）：删除指定流程。
